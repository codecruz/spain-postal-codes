An open, versioned dataset of **Spanish postal codes and the municipalities they serve**. It is built from official INE data and kept up to date automatically. You can use it in four ways:

| | |
|---|---|
| 📄 **Dataset** | [`data/codigos_postales.csv`](data/codigos_postales.csv): download it and use it anywhere |
| 🌐 **Static JSON API** | [`codecruz.github.io/spain-postal-codes`](https://codecruz.github.io/spain-postal-codes/): no server, no API key, open CORS |
| 📦 **npm package** | [`spain-postal-codes`](packages/npm): offline lookup and search, zero dependencies, ~110 KB gzipped |
| 🐘 **PHP library** | [`codecruz/spain-postal-codes`](https://github.com/codecruz/spain-postal-codes-php): the same API for PHP 8.1+, via Composer |

**10,791 postal codes · 8,132 municipalities · 52 provinces**. The current data refers to 30 June 2026.

## Where the data comes from

The dataset is generated by [`scripts/build_dataset.py`](scripts/build_dataset.py) from two official sources of the **Instituto Nacional de Estadística (INE)**:

- **[Callejero del Censo Electoral](https://www.ine.es/dyngs/DAB/es/index.htm?cid=1390)**: every street segment in Spain with the postal code that serves it. The INE publishes it every January and July.
- **[Relación de municipios y sus códigos](https://www.ine.es/dyngs/INEbase/es/operacion.htm?c=Estadistica_C&cid=1254736177031)**: the official municipality names and codes.

Both are reusable under [CC BY 4.0](https://www.ine.es/dyngs/AYU/index.htm?cid=125). Every release is reproducible: run the script for a given period and you get the same files.

Why not Correos or CartoCiudad? Correos owns the intellectual property of its postal code database and sells it. CartoCiudad shows Correos' postal codes, but its [agreement with Correos](https://www.boe.es/diario_boe/txt.php?id=BOE-A-2017-3522) forbids offering them for download. The INE callejero is the official source that can be redistributed.

### What is and isn't included

- **Included:** every postal code assigned to a street address, linked to the INE municipality code. A postal code can serve several municipalities, sometimes in different provinces (enclaves such as Condado de Treviño). A municipality can have many postal codes.
- **Not included:** postal codes that don't belong to a street address, such as PO boxes (apartados de correos) or large-volume customers.
- **Discarded as probable typos:** a handful of codes that appear in a single street segment of a municipality in another province. They are listed with their reason in [`data/metadata.json`](data/metadata.json).

## Dataset

| File | Contents |
|------|----------|
| [`data/codigos_postales.csv`](data/codigos_postales.csv) | `cod_postal,municipio_id,municipio,provincia_id,provincia`: one row per (postal code, municipality) pair |
| [`data/provincias.csv`](data/provincias.csv) | `provincia_id,provincia` |
| [`data/metadata.json`](data/metadata.json) | Source period, reference date, counts, attribution and discarded pairs |

```csv
cod_postal,municipio_id,municipio,provincia_id,provincia
01001,01059,Vitoria-Gasteiz,01,Araba/Álava
28001,28079,Madrid,28,Madrid
```

- All codes are **strings** that keep their leading zeros (`01001`).
- `municipio_id` is the 5-digit INE code, so you can join it with any other INE statistics.
- Names are the official INE names, with the article moved to the front (`A Coruña` instead of `Coruña, A`).

## Static JSON API

The site is a set of static JSON files hosted on GitHub Pages. It has no rate limits, nothing to keep running, and an unknown code returns a `404`.

| Endpoint | Contents |
|----------|----------|
| [`/v1/cp/{cod_postal}.json`](https://codecruz.github.io/spain-postal-codes/v1/cp/28001.json) | Municipalities served by a postal code |
| [`/v1/municipios/{id}.json`](https://codecruz.github.io/spain-postal-codes/v1/municipios/28079.json) | A municipality and its postal codes |
| [`/v1/municipios.json`](https://codecruz.github.io/spain-postal-codes/v1/municipios.json) | All municipalities (for autocomplete) |
| [`/v1/provincias.json`](https://codecruz.github.io/spain-postal-codes/v1/provincias.json) | The 52 provinces with counts |
| [`/v1/provincias/{id}.json`](https://codecruz.github.io/spain-postal-codes/v1/provincias/41.json) | A province with its municipalities and postal codes |
| [`/v1/meta.json`](https://codecruz.github.io/spain-postal-codes/v1/meta.json) | Data period, license and counts |

```bash
curl https://codecruz.github.io/spain-postal-codes/v1/cp/01427.json
```

## npm package

```bash
npm install spain-postal-codes
```

```js
import { lookup, searchMunicipios, getProvincia } from "spain-postal-codes";

lookup("41700");               // [{ id: "41038", nombre: "Dos Hermanas", provincia: "Sevilla", ... }]
lookup(1450);                  // leading zero restored: same as "01450"
getProvincia("08001");         // { id: "08", nombre: "Barcelona" }
searchMunicipios("alcala");    // case- and accent-insensitive
```

See the [package README](packages/npm/README.md) for the full API.

## PHP library

```bash
composer require codecruz/spain-postal-codes
```

```php
use Codecruz\SpainPostalCodes\PostalCodes;

PostalCodes::lookup('41700')[0]->nombre;       // "Dos Hermanas"
PostalCodes::getProvincia('vizcaya')?->nombre; // "Bizkaia"
PostalCodes::searchMunicipios('alcala');       // case- and accent-insensitive
```

It lives in its own repository, [codecruz/spain-postal-codes-php](https://github.com/codecruz/spain-postal-codes-php), because Packagist needs `composer.json` at the repository root. A workflow there pulls each new release of this dataset.

## Development

```
data/                 Generated dataset (committed and versioned)
scripts/              Dataset builder, static site builder and their tests (Python, stdlib only)
packages/npm/         npm package (plain ESM + type definitions, no build step)
```

```bash
python3 scripts/build_dataset.py              # rebuild data/ from the latest INE release
python3 scripts/build_site.py                 # build the static API into site/
python3 -m unittest discover -s scripts       # Python tests
(cd packages/npm && npm test)                 # npm package tests
```

### Automation

| Workflow | What it does |
|----------|--------------|
| [`ci.yml`](.github/workflows/ci.yml) | Tests the Python scripts and the npm package (Node 18–22) |
| [`update-data.yml`](.github/workflows/update-data.yml) | After each INE release (February and August), rebuilds `data/` and opens a pull request with the changes |
| [`pages.yml`](.github/workflows/pages.yml) | Deploys the static API to GitHub Pages when `data/` or `scripts/` change on `main` |
| [`publish-npm.yml`](.github/workflows/publish-npm.yml) | Publishes the npm package when you create a release tagged `npm-v<version>`, using npm Trusted Publishing (no token stored) |

## Contributing

The data comes from the INE, so the dataset files shouldn't be edited by hand. If you find a wrong or missing postal code:

1. Check whether the INE callejero has the error. If it does, report it to the INE.
2. If the problem is how this project processes the data, open an issue or a pull request against `scripts/build_dataset.py`, with a test.
